# Traceability: requirement → tests

Each acceptance criterion of [requirements.md](../.kiro/specs/console/requirements.md) and what
verifies it (R16.7). `npm run check:traceability` (part of `npm run verify`) fails if a criterion
is missing from this file, if a row names nothing, or if a row names a test, a script or a make
target that does not exist.

How to read a row:

- `` `path/to/file.test.ts › part of a name` `` is a test. The part after `›` is a piece of the
  test's full name as the runner lists it (the names of its `describe` blocks and of the test, joined
  by `>`; the `%s` of a parameterised test is part of the name). A path alone cites the whole file.
  Paths under `e2e/` are Playwright tests, which run against the real ledgerd (`make e2e`).
- `` `npm run name` `` and `` `make name` `` are scripts and targets that check the criterion (a lint
  rule, a scan of the build, a checker); their own tests are cited next to them where they have any.
- **Not automated** says what no test verifies, so that a gap is stated instead of hidden.

A reference proves that a test exists and where it is. That it _verifies the criterion_ was
checked by reading the test when the row was written, and is kept honest by review, not by the
script.
